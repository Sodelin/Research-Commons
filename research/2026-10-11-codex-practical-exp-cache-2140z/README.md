`ExpCache` stores successful immutable plain forward intervals in a bounded FIFO map, keyed by canonical rational, precision and scalar policy. Keys exceeding the caller's reduced numerator/denominator bit bound bypass caching; capacity zero also bypasses it. Failures are never cached, lookup order is deterministic with respect to requests, and hashing still checks full equality. HashMap output iteration is never used. Entry and key limits bound admitted cache storage, not all process allocations or arbitrary public API inputs.

The scalar expression order, exact intermediate rationals, dyadic floor/ceiling, range reduction, Taylor cap and width guards are unchanged. Counters saturate and do not decide results. Original `exp_neg` and `ReceiverContext::new` remain uncached APIs. `new_with_cache` optionally shares plain values across worker-local contexts. Context identity, domain and call-budget checks stay in their original order; two calls are charged before lookup, including hits. Endpoints are reconstructed through the current context's unchanged constructor and pre-rounding reduced-bit checks. Cloned contexts share their original budget; fresh contexts never share budgets. A held cache borrow falls back to the pure uncached calculation without adding a refusal/panic. The library still forbids unsafe code.

The probe adds an explicit `--cache-entries N` experiment option with entries<=4096; unchanged stdout wires are compared exactly because this bounded adapter's inherited wire contract explicitly specifies them. Cache statistics go to stderr. This option does not wire caching into the deployed producer or checker.

**HAND-DERIVED ARGUMENT:** initially each stored row is absent; insertion stores exactly the successful pure scalar function at the full key, and hits return a clone of that row. Eviction/bypass only causes recomputation of the same function. The receiver performs its existing semantic checks/charge before choosing either pure path, then its existing rounding/bit constructor. Under ordinary successful execution this preserves numerical/refusal/call semantics. The finite tests below challenge that argument; neither this induction nor a hash is a Lean proof or a universal host-OOM/runtime guarantee.
