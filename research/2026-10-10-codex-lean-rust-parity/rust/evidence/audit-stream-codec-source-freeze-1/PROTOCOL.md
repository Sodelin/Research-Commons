# Pinned saved-audit monotone copy/literal codec derivative

This is a new standard-library data-storage helper. It leaves the original `08f6c11c…` prototype, its scratch, and every accepted audit/export unchanged. Its inputs must be independently captured existing raw audit files and the existing portable base gzip, with exact absolute paths, byte lengths and SHA-256 digests. It neither creates an audit nor decides whether a source theorem or graph is admitted.

The wire format remains exactly `RC-AUDIT-COPY-LITERAL-V1` plus NUL (25 bytes), base raw SHA-256 (32 bytes), target raw SHA-256 (32 bytes), target length (u64 little endian). `C` carries u64 offset and u64 nonzero length; `L` carries u64 nonzero length followed by that literal payload. Operation order defines target byte order. No JSON reserialization or implicit path/count substitution occurs.

The producer authenticates base raw, compressed base gzip and target raw identities before creating a patch. It fully decompresses/checks the portable base against its pinned raw counterpart. Only the base is mapped. The base declaration-boundary recognizer retains the original serializer-specific top-field and record-span shape; new target records are streamed through a bounded string/brace scanner and checked as six-field declaration objects. Headers, separators, tails and changed/new records stay literal. A same-name base candidate is copied only after digest and direct byte equality, and only if its source offset is at or after the end of the previous copy. Otherwise its exact bytes remain literal. This monotone restriction makes no claim that a future target preserves old declaration order or will compress sufficiently.

The producer writes directly to a create-new bounded gzip, hashing/counting the uncompressed patch stream. It creates no raw-patch or second target file. The returned patch pin binds compressed path/length/digest, complete raw patch length/digest, base/target length/digest, exact C/L/total operation counts, target decoded length and the monotone-copy requirement. A separate patch-pin artifact must be preserved before restoration. Failure leaves partial create-new output for diagnosis and cannot yield a successful pin.

Restoration first authenticates the compressed patch, then parses the entire raw patch without writing output or invoking a consumer. It verifies the raw patch hash/length, exact header, opcode/count pins and final decoded size. Nonzero C ranges are within the pinned base and monotone/nonoverlapping. C and L target position-plus-length checks occur before reading/emitting payload. Literal length must also fit remaining pinned raw patch bytes. Unknown opcodes, truncated fields/payloads, extra bytes, over-counts, wrong hashes and invalid ranges refuse. Thus the previous prototype's post-write literal overflow check is replaced by a full pre-output validation pass.

After preflight, base raw/gzip and target raw identities are authenticated using bounded reads. The optional output path is exclusive and size-precharged; its default allowance is16MiB and the trial writes only6,629,112 bytes. The normal mode produces no restored file. A second patch pass rechecks all bounds and raw hash while decoding. The portable base gzip is consumed exactly once in source order. Skipped and copied base bytes are all hashed and compared with the authenticated raw base before copied bytes reach the sink. Every target piece is compared with the authenticated actual saved target before optional output or callback. Final target SHA/length, complete base SHA/length and base gzip EOF are mandatory before success.

Successful stream comparison therefore requires no new large raw base or second target artifact. It still requires the independently produced original raw target as a fixed comparison input: it does not remove a future compiler's114MiB scratch-audit requirement. A gzip-only portable replay without an existing pinned raw base/target is outside this interface. The trial uses only existing accepted1504 and168; no1505/1506/1570 audit is synthesized or accepted.

The worker/driver enforces256MiB RLIMIT_AS. Hard resource ceilings are128MiB raw input,1MiB line,2MiB record,200,000 records,500,000 operations,192MiB uncompressed patch stream,32MiB gzip/scratch/output. Trial gzip cap is1MiB and trial scratch cap32MiB. Target is never mapped. Literal buffer≤1MiB; transfer buffers≤64KiB. Scratch byte usage is checked before patch writes and optional output allocation. Memory or export-limit refusal is a preservation failure, never theorem failure or mathematical infeasibility. Bounded callbacks are caller-owned; the frozen driver hashes/counts only. Existing input files are excluded from new scratch allocation and remain untouched.

Source and format are frozen for Design static QC. Fresh byte exercise is pending root approval after that review. `SCENARIO.json` pins the exact known inputs, proposed eight focused cases, address-space/scratch limits and scheduler/root argv. The cases compare the streamed producer with the old exact raw patch, exercise stream-only and optional exclusive restoration, and reject wrong compressed/raw hashes, an authenticated oversized first literal, existing output and insufficient optional-output allowance before any new output/consumer piece. The optional small restored file is deliberately within32MiB; no second large114MiB file is permitted.

For a later new actual union, its raw target must first be independently produced/pinned. Root must approve its exact plan and portable-output budget; existing trial success cannot predict final-union copy density, compressed size, compiler logs or total capacity. All mathematical/source/compiler acceptance remains in its original receipts.
