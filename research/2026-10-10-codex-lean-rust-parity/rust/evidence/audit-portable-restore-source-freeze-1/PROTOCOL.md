# Portable pinned streaming audit restoration

Contributor: Codex / rust_implementation. This NEW derivative preserves the accepted `cdb613` codec and `edea7` fixed-pair trial. Source/static freeze only; the nine-case trial is pending independent Design QC and root approval. Byte restoration does not create or accept a theorem audit.

Required inputs are one pinned base gzip, one pinned C/L patch gzip, a pathless expected raw base identity, a pathless expected raw target identity, exact patch pins, and an existing bounded scratch directory. No raw base/target file is required or opened by the default restorer. `PortablePlan` uses schema `audit_portable_restore_plan_v1`, exact fields `base_gzip`, `base_identity`, `target_identity`, `scratch_root`, and `limits`; identities contain only `bytes` and `sha256`. Compressed pins contain only `path`, `bytes`, `sha256`. It reuses the exact existing `audit_copy_literal_patch_pin_v1`. Duplicate JSON fields, noninteger metadata, Bool counts, invalid digest shapes, and unknown fields are refused by the pinned decoder. The existing limit fields/hard ceilings remain unchanged.

`audit_portable_restore.py` authenticates the unchanged `audit_copy_literal_codec.py` SHA256 `cdb613eab954437ea47a441f5bd0e2bfdddb98e835a7ed1cd21559056f54257c`, then executes those exact bounded source bytes under a private module name. There is no mutable-path fallback or call to its old producer/restore. Distribution must include that exact source beside the NEW wrapper. This is explicit source reuse of its FilePin/Limits/PatchPin validation, raw patch reader, full preflight, and monotone operation parser; new pathless cursor/sink code removes mandatory raw references.

Wire format stays byte-for-byte compatible: 25-byte `RC-AUDIT-COPY-LITERAL-V1\0` magic, 32-byte raw base hash, 32-byte raw target hash, and 8-byte little-endian target length. `C` is an 8-byte source offset plus 8-byte positive length; `L` is an 8-byte positive length and exact payload. C offsets must be monotone/nonoverlapping. Complete target length, raw patch length/hash, operation/copy/literal counts, every copy range, and every literal range/payload length are pinned and checked.

Both compressed-file digests pass before output/callback. Complete patch decompression/header/count/range/hash preflight passes before output/callback, including pre-read/pre-write literal and copy bounds. Restore then consumes the base gzip once, hashes skipped/copied/all remaining tail bytes, and hashes the full target stream. Only successful final base and target hashes permit a success result. Chunk size is at most 65,536 bytes. Neither base nor target is mapped or materialized by the default restorer.

Callback pieces are PROVISIONAL until the function returns successfully: an incorrect final raw identity may be detected after chunks have been emitted. No callback or partial create-new output implies accepted byte identity. Optional files remain at their create-new path on failure, clearly lacking a successful result; there is no overwrite. Compressed digests and preflight reject before callbacks, while final raw digest controls deliberately exercise post-stream refusal. A consumer must publish a decoded artifact only after successful return.

`restore(plan, patch_pin, output=None, on_piece=None, compare_base_raw=None, compare_target_raw=None)` is callable. Comparison pins, when expressly supplied, must match the corresponding pathless identity and are fully authenticated before callbacks. Every corresponding chunk plus EOF is compared. Returned `optional_base_reference_checked`/`optional_target_reference_checked` flags distinguish that mode from ordinary compressed-only restoration. `required_raw_reference_files` is always zero. Default restoration still validates both complete raw identities cryptographically.

CLI: `python3 audit_portable_restore.py --plan PLAN.json --patch-pin PATCH-PIN.json` restores to hash/status only. `--output NEW_FILE` permits exclusive bounded output in the declared scratch directory. `--compare-base-pin FILE.json` and `--compare-target-pin FILE.json` explicitly enable independent raw comparisons; their absence has no raw-file requirement. Plans/pins are bounded to 65,536-byte JSON frames. Exit 0 only for full success; exit 1 is refusal/execution failure with no acceptance claim. The CLI uses the preserved codec's 256 MiB address-space enforcement. Direct library callers require the approved capped worker.

Hard/default limits inherit the accepted codec: raw identities at most 128 MiB; raw patch at most 192 MiB; default compressed patch at most 1 MiB (hard ceiling 32 MiB); at most 500,000 operations and 200,000 C spans; scratch at most 32 MiB; default optional output at most 16 MiB (hard ceiling 32 MiB). The producer-only record/line fields remain present for exact limit schema compatibility. Existing directory usage plus an optional target's complete pinned size is charged before output creation. No full 114 MiB optional target artifact is allowed by this scope. Address-space/RSS and scratch are measured in the approved trial; defaults are not a future compression promise.

Frozen trial uses only the existing accepted1504 compressed base and168 compressed patch. The first standalone call receives no raw comparison pin; a separate driver callback compares every emitted byte to the original168 target and hashes it independently. A second call explicitly requests both raw references. Three malformed compressed/range controls must expose no target callback/output. Two corrupt final identity controls carry valid compressed/raw patch pins and stream provisional bytes, then must fail the final target/base hash without returning verification success. Output-budget and existing-output controls must refuse before callback/write. No large raw artifact, new audit, mathematical/compiler/native/reference process, or old eight-case trial is created/run. Fresh execution awaits root approval after source QC.

Original cdb fixed-reference tool remains useful for its already accepted byte validation; this derivative alone supplies the missing compressed-only restoration interface. A future actual1570 requires an independently produced/pinned patch and a newly reviewed scenario/storage budget. Nothing in this freeze synthesizes that output or guarantees its capacity.
