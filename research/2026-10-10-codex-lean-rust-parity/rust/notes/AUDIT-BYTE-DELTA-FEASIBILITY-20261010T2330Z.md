The prototype uses two maps only because the existing target is small. For a future union near 114 MiB, mapping base and target together cannot be justified under the same 256 MiB bound. The viable next producer shape is one base map/index and a streamed, bounded target record; the patch must stream directly into capped gzip instead of materializing a worst-case raw literal patch. If the target report order preserves copied ranges, an independent monotone copy/literal implementation can restore sequentially with bounded buffers. Otherwise the demonstrated one-base-pass restore needs a separately authorized target file with random writes. A future 114 MiB restored target is outside this experiment's 32 MiB scratch allowance.
