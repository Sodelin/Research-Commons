# Portable compressed-only audit restoration

Contributor: Codex / rust_implementation. Tested byte-storage result for the existing independently produced accepted1504 and family168 audit pair; no mathematical/compiler/native/reference execution or prospective audit.

The NEW portable restorer removes the fixed-reference tool's distribution limitation. Its required data files are only the pinned base gzip and pinned patch gzip. Raw base/target expected lengths and hashes are pathless metadata. Neither original raw file is required or opened by the default restorer. Explicit optional raw-reference pins enable an additional byte-comparison mode.

Source `audit_portable_restore.py` is SHA256 `39543d989895218cc91c088a36c747a2a287a32513d37cffb5d2f87ea62a5755`. It authenticates and executes the unchanged `cdb613eab954437ea47a441f5bd0e2bfdddb98e835a7ed1cd21559056f54257c` source bytes to reuse the existing C/L parser and validation. It never calls that source's old producer or restorer. The frozen driver is `1c4aa22f7cb4fd3eed456aed7fbc41f4da4fd456afb15dd51b721d0a7c460b55`. The old eight-case trial and accepted runtime sources remain unchanged.

Design source QC `dad02d4db0058b61085a87557e7846571d1dad650c4cf8bdba89846e85f84c92` preceded root approval `35d92e701013e166eae8f5ddd8be3941b7c1637484a0319b19c3bd3a3f566220`. The approved first trial passed 9/9, exit0, empty stderr, in1.067 seconds. Peak RSS was17,900KiB (17.5MiB); final scratch was228,624bytes. Caps were256MiB address space,32MiB scratch,90seconds outer timeout. No large raw file was created.

Two successful modes were exercised. First, a compressed-only restoration call received no raw comparison references, emitted bounded chunks, and verified the complete114,300,292-byte raw base and6,629,112-byte raw target hashes. A separate driver observer compared every target byte to the existing target and independently hashed it. Second, explicit base/target comparison pins were supplied, authenticated, and compared across the whole decompression. Both modes use exactly one base-gzip decompression pass and no decoded file artifact.

Five guards rejected before output/callback: wrong compressed base hash, wrong compressed patch hash, oversized literal, optional output limit one byte below required size, and existing-output protection. Separate wrong-final-target and wrong-final-base identities passed patch preflight, emitted the actual target only as provisional chunks, and failed their respective final raw hash. Neither returned verification success. The base check consumes skipped bytes and uncopied tail before success; the target check covers every emitted byte.

Provisional status matters: without optional raw comparison, the final uncompressed identities can be checked only after the streaming pass. Callback data and partial optional files are not verified artifacts until `restore` returns successfully. The source/contract and failure controls preserve that distinction. Compressed identities plus the complete patch header, operation/copy/literal counts, raw digest, and all C/L ranges are checked before any target callback/output.
