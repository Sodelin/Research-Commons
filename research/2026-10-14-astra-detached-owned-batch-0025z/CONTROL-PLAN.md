# Future owned guard/capture composition controls

Source-only plan. No control below has run, and no new suite is implemented. Root/Lean owns scheduling; external compilation keeps its slot. Reuse the existing tested detached transport and namespace controls, preserving their own pins and receipts. Do not repeat their process identity, pidfd cleanup or namespace lookup corpora.

Use bounded synthetic owned-state and guard-output fixtures in a new isolated test directory when explicitly scheduled. Do not substitute fixture objects for production compiler evidence, modify the fixed production source/state, launch a real builder, or claim real Lean compilation. Pin the executed driver/helper/test sources and preserve each failed control before repair.

| Focused case | Required observation |
| --- | --- |
| External closure incomplete | Missing receipt/log, failed metadata, orphan index or wrong selected plan refuses before guard launch or owned-state creation. A synthetic complete metadata set remains only a preliminary gate; it cannot claim source/object authentication. |
| Current external scheduler active | A labelled process inventory containing `one_batch_small.py` is refused as occupied. Reuse existing process-inventory control machinery; do not start or signal a production scheduler for a test. |
| Closed prior state changed | A changed indexed receipt, log, copied Lean source, PLAN or NAMESPACE body, or a changed prior delta hash refuses the resumed batch. Verify the evidence survives unchanged. |
| Ordinary failed builder | Preserve completed invocation records and eventless bytes, original copied sources and PLAN/NAMESPACE delta. Report unsuccessful provider preparation and no automatic successor. |
| Requested stop or guard exception | Even a child exit code of zero cannot promote success. Preserve all changed bytes before interpretation, bypass the generic success capture branch, and keep OS guard exit unknown. Existing transport stop/identity tests are reused. |
| Missing/malformed terminal or capture mismatch | Preserve the delta and write an unverified finish/error; missing receipt or capture failure cannot become verified compilation. |
| Fresh, new clone and resumed accounting | A synthetic batch with prior receipts, new authenticated-reuse receipts and fresh compiler events reports the three quantities separately. The builder's cumulative reuse total must equal prior receipts plus new clones; it is not relabelled as new clones. |
| Short incomplete or over-budget batch | A successful-looking summary with fewer fresh events than requested and an incomplete provider prefix, or more than the explicit budget, is refused. A genuine completed provider prefix may stop short, while final adapter/Lake/audit flags stay false. |

These cases test the new driver/capture composition only. The authoritative production prerequisite remains the pinned builder's full source/log/object/namespace checks under its fixed guard. No synthetic control can satisfy that prerequisite or the separate actual final Lake target and axiom audit.
