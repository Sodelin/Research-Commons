# Actual-source adaptive policy verification and execution

A supplied finite observation-dependent policy can now be verified against a
complete actual-source export and executed on a coherent exact-law history.
The verifier checks the whole policy, rather than only its separate calls or a
single response path. A successful policy is a constructive witness for its
declared at-most PATH budget. Automatic synthesis of a policy remains open.

`verify_actual_policy.py` runs the inherited original graph census and law
compiler, requires complete catalogue exhaustion, and binds actual targets.
It then calls `verify_policy.py`, which keeps ONE original parameter vector
through all observations of each source model. No history row receives a fresh
fit. A partial catalogue returns UNKNOWN before policy verification.

At each policy node the verifier substitutes the actual deterministic law
response generated by that same source. Guards and action weights may read only
earlier observed coordinates. Hidden source parameters and future responses are
rejected. Every reachable denominator must be nonzero. Every action must have
exactly its declared positive support, zero weights outside it, and sum one.
Every path must satisfy the union-of-configurations and original-sites budget.
Decision guards use a deterministic first-eligible convention. Their union must
cover ALL source-generated reachable histories, and each reachable leaf must
return that source's actual target.

These are universal real-source obligations. The implementation checks their
existential counterexamples by exact Z3 QF_NRA. Thus a completed UNSAT check has
SAME_BACKEND trust; it is not an independently replayed generic proof certificate
or a Lean proof. Unknown/time/node limits stay UNKNOWN. An invalid or refuted
candidate never proves that the requested budget is losing. Impossible initial
histories are separately reported and cannot yield a vacuous target result.

The current recursive implementation also has explicit machine resource
ceilings: policy depth 128, guard depth 64 and expression-evaluation depth 64.
An iterative policy preflight and recursive-binding error guard return UNKNOWN
for deeper trees, independently of a larger node budget. These are implementation
limits, not mathematical bounds on the policy or original source class.

The current policy syntax supports finite trees with rational arithmetic
expressions in earlier response coordinates, nonnegative integer powers and
semialgebraic guards. This can produce irrational action values from irrational
responses. Algebraic root-section functions from general CAD selectors are not
yet encoded. The execution codec currently accepts rational response vectors;
other encodings return UNKNOWN. Neither restriction is silently promoted to the
full inherited semialgebraic-selector contract.

The concrete adaptive replay uses the unchanged accepted nine joint images of
the complete 546-source four-taxon/one-hybrid class. It checks the genuine policy
forcing0, then response-dependent weights (h[0],1-h[0]), then actual target
guards on the second response. All 162 exact source obligations pass, together
with 12 adversarial controls. The model reduction is pinned to the accepted
actual-source joint-image provider; the verifier does not reconstruct its census.

The actual-export workflow uses the previously accepted complete 15 ordinary
quartet trees, with identical model bytes (SHA-256 78da02b2099204557d1414aec1d10c1dd2063b22e012c72834b00dafe985c402).
It verifies the passive candidate, executes its actual original-tip-labelled
unrooted readout, and retains one original source assignment for each complete
history admission check. This is an interface control and not a new source case
or a claim that a passive example closes adaptive G7.

Install the pinned `requirements.txt` versions, then run:

    python3 test_policy_verification.py
    python3 verify_actual_policy.py ACTUAL-SOURCE-POLICY-REQUEST.json --output fresh-verification
    python3 execute_actual_policy.py ACTUAL-EXECUTION-REQUEST.json --output fresh-execution

Targets in policy leaves use the original compiler's complete engine-labelled
target serialization, not just arbitrary target codes. The source design fixes
the original registry, readout, mechanism menu, forcing configurations and clock
contract. Unsupported data and nonempty empirical-admission metadata fail closed
through the inherited source adapter. This workflow does not admit DNA/counts as
exact genealogy laws, infer unknown-size termination, or certify empirical fit.

The decisive remaining implementation gate is automatic source-admitted
adaptive selector synthesis with complete reachable response regions, including
general algebraic CAD sections. This finite-candidate verifier can check and
execute a proposed selector without waiting for that search to become complete.
