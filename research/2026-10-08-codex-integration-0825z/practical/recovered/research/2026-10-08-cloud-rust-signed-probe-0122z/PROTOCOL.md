# Signed-nine fixture probe

Status: source preparation; no build or execution at this capture. Author: Cloud practical lane. The source-reviewed frozen library is reused by path dependency, without edits. This TSV transport is a test probe, not the production solver or a parser for arbitrary Python objects.

One LF-terminated ASCII row is `pair`, identifier, precision, arithmetic-bit budget, exponential-call cap, mode, followed by ordered endpoint strings, separated by TAB. Mode `default` has 42 fields: six header fields and two mean boxes of 18 endpoint fields each. Mode `boxes` has 78 fields and appends two physical boxes. Mean order is AC1, AC2, CC1, BC1, BC2, AB1, AB2, AA1, BB1; physical order h, u, v, rA, rB, rC, rAB, rR, g. Each box supplies low then high for every coordinate. Both physical boxes are explicit or both default; the probe does not expose a mixed-option transport. The typed library supports the broader optional form independently.

Transport limits precede kernel work: 32,768 bytes per row excluding LF, 4,096 per field, 96 rows per process, identifier 1–64 ASCII letters/digits/underscore/hyphen, three integer fields with optional minus and 1–10 ASCII magnitude digits, each fitting i32. Control bytes except TAB are rejected; CRLF and non-ASCII are outside this declared transport. Oversized rows are consumed without retaining their unbounded tail. An extra 97th row yields PROBE_ROWS and terminates the input session. EOF without LF yields PROBE_FRAME. These are finite transport refusals, not claimed Python-object behavior.

The frozen Request validates precision 64–128, arithmetic bits 256–16384, and call cap 0–32 before endpoint parsing. Rational endpoints retain the frozen parser: 158-character cap, optional minus on an integer or numerator/positive denominator, at most 78 digits per integer, raw numerator/denominator at most 256 bits before reduction. Mean endpoints must lie in [0,1]. Original physical D: h,u,v in [1/32,1/8], five rates in [1/2,6], g in [1/6,2/3]. These validation sites are unchanged.

A receiver response has 16 fixed fields: result, identifier, status, refusal-or-`-`, charged scalar exponential calls, precision, bit budget, cap, Python-reference provider SHA256, native_exact_interval_core, then six zeros. Those zeros mean confidence certificate false, outer cover false, mean-band coverage admission false, compatible-source existence false, source-forward evaluations zero, and observation rows replayed zero. Rust does not claim that its native kernel executed the Python provider bytes. The SHA identifies the comparison reference.

Completed geometry appends 42 fields: nine low/high difference pairs in physical order; nine normalized absolute bounds in physical order; maximum normalized bound; seven low/high signed residual pairs in root, root_time, h, g, AB1, AB2, BB1 order. Thus completed responses have 58 fields, including completed geometry with UNKNOWN status. Refused responses have only the fixed 16 fields and status UNKNOWN. Strict maximum <1/20 gives CONDITIONAL_PAIR_WIDTH_CERTIFIED; it admits no confidence or source feasibility. A transport response is `protocol`, safe identifier-or-`-`, refusal code, and carries no geometry.

Expected comparison fields come from execution of the authenticated Python receiver byte buffer. Exact endpoint strings, normalized values, all residuals, strict status and refusal/call-charge are compared; execution-provenance fields are intentionally distinct. No production parser, forward evaluator, search scheduler, complete outer cover, data replay or statistical admission is added here.
