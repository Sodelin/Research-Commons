## Simplest proposed arrangement

Use a one-shot process around the existing official-SDK adapter, with a user-entered secret delivered through an approved managed secret binding or the user's OS secret store. The user enters the value directly in that secure facility, outside chat, repository and tool inputs; tools may report only binding readiness. Restrict credential access to the prediction process and never return environment values, secret contents, request authentication metadata or raw SDK exception objects to model-visible tools. A user-run local process outside the agent executor is preferable if the selected environment cannot isolate the key from unrelated worker processes.

This arrangement needs no MCP service. A persistent MCP service is an optional later deployment with explicit approval, the same operation policy, authenticated callers and server-side secret storage. It must not offer generic HTTP, arbitrary SDK calls, arbitrary destinations, shell execution or user-supplied headers. The proposed default remains no persistent service and no activated credential binding. Independent inspection of the recovered private provider found one metadata read inside each prediction: the current four-scenario path therefore makes at least eight RPC method calls before SDK retries. The proposed five-attempt pilot requires a separately reviewed shared-metadata cache/bounded adapter; wrapping the existing provider alone does not meet that policy.

## Concrete pilot policy to review before activation

| Control | Proposed bound |
|---|---|
| Data | One specifically approved public reference manifest; match assembly, annotation, window/guard hashes and REF alleles. No personal genomes, arbitrary uploaded sequences, plant-to-human model transport or full Atlas download. |
| Operations | At most one metadata read and four `predict_sequence` calls: REF, A, B, A+B. No training, writes, bulk scoring, unrestricted variant queries or repeated search. |
| Inputs | Exactly two nonoverlapping validated substitutions in one fixed 131,072-base supported window, maximum three explicitly requested supported modalities and four predeclared endpoint summaries. Indels and unavailable junction/PSI endpoints are initially refused. |
| Identity | Explicit SDK/model enum, species, tissue, track IDs, annotation and settings digest shared by all scenarios. An SDK/model enum is not an immutable server-weight pin. |
| Quota | Maximum five authenticated RPC attempts for the entire pilot; no automatic retries, parallel requests, or replacement scenarios. Disable and independently verify SDK-decorator, application and gRPC retries at the underlying RPC-attempt layer; if the inherited retry wrapper cannot be disabled, refuse activation. Atomically and durably reserve every authenticated attempt in a non-secret counter before sending it. A timeout, crash or uncertain send consumes its reservation; restart never resets the budget. Counting public method calls alone is insufficient. |
| Resources | One prediction process; at most60seconds per call,300seconds total and32MiB aggregate accepted output. Enforce gRPC max_send_message_length2MiB/max_receive_message_length8MiB before deserialization and a1GiB process address-space limit, plus hard process termination, cancellation attempt and explicit partial-result status. The inspected factory hardcodes unlimited message limits: a separately reviewed supported bounded-channel adapter is required; if it cannot enforce transport/process limits, refuse activation. Post-receipt size rejection alone is insufficient. A local kill may not cancel server work and must not trigger retry. These are proposed controls, not tested SDK guarantees. |
| Cost | No activation until the account's actual terms/quotas/cost policy is checked and Nolan approves a concrete bound. Unknown billing or potential unapproved charges refuses activation. No claim of free service is assumed. |
| Logs | Record only request ID, approved manifest/scenario/settings hashes, SDK/model identifier, start/end, reserved call number, endpoint availability and enumerated status. No key, authentication headers, environment dump, raw sequence, participant data, raw exception or unreviewed prediction artifact is logged or published. |
| Revocation | Disable the local binding/service first, cancel pending work, revoke/rotate the key in the provider console, remove secret access and verify readiness becomes unavailable without reading the key. Previously disclosed keys require provider revocation, not only deleting a local variable. |

Activation requires recovered private adapter review, permitted public-data manifest, current service/output terms, allowed host/TLS and actual bounded transport support, account quota/cost evidence, explicit live-pilot approval, and separate approval for any new persistent access. ## Scientific meaning and offline continuation

Compute predicted interaction only from four matched sequence predictions on the declared scale, `yAB−yA−yB+yREF`; single-variant percentiles cannot supply combined-haplotype effects.
