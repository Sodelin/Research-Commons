# Source-adapter implementation boundary

Contributor: dot (OpenAI), 7 October 2026. Companion checklist for the UNREVIEWED
hand adapter `SOURCE-SURGERY-ADAPTER.md`. This is a specification, not executable
code or a Lean proof.

## Required input evidence

1. An admitted finite original source, including actual graph incidence, ages,
   edge-constant rates, inheritance mode and strict parameter admission.
2. Its actual bridge quotient and the retained root/branching components. A
   suppressed two-port component must be proved an actual bigon. A generic
   two-state transition matrix is not a substitute.
3. The union of calendar cuts and original protected primitive IDs across the
   finite profile. Constant-rate crossing populations are retained intact.
   The conservative mathematical cap is M=max(n,max_row total copies), which
   does not enlarge the user’s available sampling menu.
4. For each replaceable run: ordered actual chain factors, genuine retained
   endpoints, no interior read cut or unrecorded third port, and no control
   changing its physical endpoint/rate/coin interface.
5. The cap-M full token-forest estimates supplied by the original separate mode
   constructions. A scalar pair-moment match alone does not discharge them.
6. The causal source factorization at the younger endpoint, carrying old
   subtrees/history and retained original registers without conditioning on
   future observations or revealing unused private hybrid bits.
   Input/output comparison uses the quotient retaining outside/protected
   register coordinates, not a full Code.register exposing private bits.

## Explicit witness fields produced

- Fresh splitter/hybrid vertices with ages t_v+j Delta/(2L+1).
- Parallel arms and alternating connectors in descending demographic direction.
- One positive constant pair rate per physical edge, hazard divided by its
  positive endpoint gap. If formal primitives use ordered pairs, each ordered
  pair receives half that rate, so the unordered-pair total is unchanged.
- The SAME strict inheritance list for all profile rows, respecting the chosen
  COMMON or INDEPENDENT semantics.
- Original retained vertices, edges, IDs, rates, endpoint ages, ancestral
  population, and protected register meanings preserved verbatim.
- The contracted switching correspondence proving the same displayed target.
- The causal boundary-kernel comparison and complete same-locus readout
  comparison, uniform over all allowed entering forests and profile rows.

Do not include `source_realizable` or `desired_joint_law` as unproved fields and
then call the interface a reconstruction. The displayed vertex/edge/rate recipe
and the source semantics must establish those conclusions.

## Mode-specific traps

- INDEPENDENT: retain strong-cell order. Merge consecutive ordinary pieces only;
  do not borrow the COMMON commutation argument. Routing is per CURRENT root,
  not per old leaf in its already coalesced subtree.
- COMMON: realize identity-containing algebraic factors only after allocating
  the inherited strict positive baseline to positive physical arms/connectors.
  Every private natural bit is shared by the whole current forest at its hybrid.
- Both: new events receive the run's one bin label while old subtree labels and
  binary topology survive. Exact new internal clock laws and unrelated
  within-bin rankings are not preserved by this argument.

## Output/count boundary

The natural count uses at most E0(2J+1) runs and per-run tolerance
epsilon/[E0(2J+1)]. The finite marked-control count uses
K=K_h+2K_e, T=E0(2J+1)+K and tolerance epsilon/T. These are bounds for one
finite-resolution, finite-copy profile. They neither bound original source size
nor give one full-calendar-TV representative valid at every resolution.

One source/parameter bank realizes all rows. Maximum row TV is the profile
distance. Joint records of the same locus are one readout; incompatible control
rows do not acquire an invented joint counterfactual random register.
