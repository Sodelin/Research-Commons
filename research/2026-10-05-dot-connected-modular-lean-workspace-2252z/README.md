## Reproduction

The exact executed build scripts, Lake entrypoint, dependency graph and source bytes are in `package/`. Sources are stored once as `source-store/<SHA256>.lean`; the dependency graph maps logical names to exact versions and contexts.

The tested and supported replay environment is Linux: the builder uses fcntl and checks the exact Linux compiler binary SHA256 e8baaa71855a616dc351028f3ad2200051b0671f423a1696a100e809302d5550. Native Windows/macOS execution has not been configured or checked. Use the pinned existing Linux Lean 4.33.1 distribution (commit 819816b2e0a3bf405af45ae5c7af2491d8f5bee6) and an already-built Mathlib checkout at commit 0df444a360eaa60ab8c11dca51a86af692955474. Set CONNECTED_LEAN_BIN to that Lean distribution's bin directory and CONNECTED_MATHLIB to the Mathlib checkout, place the pinned bin directory on PATH, and run from `package/`:

- `lake build`: all 44 targets, serially.
- `lake test G1-467/G1-complete`: original complete G1 group.
- `lake test NANUQ53/NANUQ53`: original standalone NANUQ53 context.
- `lake test integration/curve-adapter`: explicit new connection context.
- `lake test connected/compatible`: combined context using the reviewed adapter and FeedbackDynamics v2.
- `lake test connected/feedback-legacy`: isolated older FeedbackDynamics context.
