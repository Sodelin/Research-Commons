# A zero-run has an exact triangle component

In the actual unmerged two-sheet graph of [round three](../round3/ROUND-3.md), each positive zero start n gives a same-sheet triangle on coordinates n through n+2. The Lean endpoint `ResearchCommons.TriangleRun.exact_component` uses the actual sorted graph-triangle edges, not assumed interval adjacency. For a positive run of m consecutive zeros with two separating ones on either side where applicable, the reachable component consists of exactly m+2 distinct vertices in each sheet. Arbitrary deletions strictly below the run preserve this component. A separate theorem `late_component_iff` checks the converse local step: if all deleted coordinates are at most D and a retained component lies entirely above D+2, that component is unchanged from the original triangle-edge graph. `one_gap_connects` is a checked negative control: two triangles separated by only one switch still connect.

The new endpoint starts at a supplied run. It does not construct a switch sequence with arbitrarily late runs of each encoded size or assemble the merged-root, countable-portfolio theorem. Next: build the fixed-width slot generator and prove the recurrent component signature, then connect to the checked host component and diagonal arguments. No fixed-source-color claim.

For replay, put the pinned [TwoLiftTriangle.lean](../round3/TwoLiftTriangle.lean) alongside TriangleRun.lean. Run `sha256sum -c SHA256SUMS`, then use pinned Lean 4.33.1 with the directory on `LEAN_PATH`, compile TwoLiftTriangle to its olean, and compile TriangleRun. The fresh two-file run took 1.049 s, standard axioms only and no sorryAx. The bounded finite exploration led to the theorem shape; the endpoint does not rely on that exploration.
