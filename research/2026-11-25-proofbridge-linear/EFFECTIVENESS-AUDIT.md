## Evaluation and investment order

1. Finish one exact theorem, with stable IDs for open proof obligations and an independent consumer checking the original scope and hypotheses. Do not upgrade a canonical claim from a receipt alone.
2. For remaining obligations capture distinct measurements: source search, authoring, type repair, compile, scheduler wait, manual interventions, and whether a reusable checked result survived an independent acceptance pass. Compare on comparable obligations against a direct Lean-first baseline; the existing stopwatch does not measure authoring speed.
3. Prefer exact reuse, then missing-interface work, then full rewriting. Queue a new proof format only if multiple real remaining arguments need it. Recheck changed transitive inputs rather than building faster with unsafe cache skips.
4. Test automated throughput only on a representative accepted input batch with status accounting; report unsupported prose separately. Track distinct exact claims, not files, commits, or the number of lane reports.
