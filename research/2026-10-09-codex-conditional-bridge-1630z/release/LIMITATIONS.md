# Runtime and recovery

Use Python 3.10+ on POSIX with `resource`. Standard-library launch paths need
no network, credentials or global installation. Optional bounded backend
requirements and pinned scratch provisioning are recorded in the bounded
packet; absence is explicit UNKNOWN. Child processes use a minimal environment
and bounded CPU, wall, memory and output limits. These practical caps can
interrupt valid work and are not mathematical completeness bounds.

Every output directory must be new. After an identity error restore trusted
source bytes and use a fresh output path. After process or resource failure,
inspect the preserved result, launch receipt and logs. Do not edit expected
hashes, patch a saved journal into acceptance or relabel a saved receipt as a
fresh run. A separate independent recheck authenticates and semantically
replays a complete prior journal. Keep failed attempts available for review.
