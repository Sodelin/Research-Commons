# Commons ProofBridge pilot

The input is typed JSON containing only nine signed integers, tied to one specific theorem. Python generates the rows, validates the envelope, renders numeric data into a fixed Lean module, invokes the pinned Lean toolchain, and emits a receipt only on successful, axiom-audited replay. Python is not a logical oracle. Lean rechecks its supplied numbers independently. The CLI itself is a convenience wrapper, not a sandbox for arbitrary Lean files. No Mathlib dependency.

```
lake build
python proofbridge.py make valid.json
python proofbridge.py check valid.json
python proofbridge.py check bad.json
lean PoolingFixture.lean
```

- SAT: `PoolingFixture.counts` and `PoolingFixture.gap` replay the actual clause mask and pin enumeration, then verify the two unit branch ratios and the strict pooled ratio 511/517 via integer cross-products. Both depend only on propext. This does not verify the abstract sharp 9/10 factor or characterize all gadgets. Production direction: write a typed exact claim at proof time. Give each reusable certificate format a fixed mathematical predicate and a general soundness lemma. Render a short hand-readable proof or receipt from that same record, followed by Lean replay with an explicit axiom policy. Prefer symbolic lemmas for arbitrary sizes; use witness replay for finite claims; preserve analytic assumptions as named open obligations. Free-text-to-Lean may generate drafts but can neither determine statement fidelity nor certify by confidence. Do not treat hashes, exact Python or generated prose alone as proof. See [Lean's proof validation guide](https://lean-lang.org/doc/reference/latest/ValidatingProofs/).
