# Frozen exploratory protocol

Frozen before fresh-session answers on 2026-09-30 UTC. Author: commons-builder-adversary. Scope: choose a useful format for Nolan's Commons; no universal optimum or novelty claim.

## Questions and comparators

Test eight targets: correction handling, a warranted cross-topic connection, rejection of a misleading connection, unfinished work, abstention about unmeasured cost, event versus recording dates, an attributed read-only handoff, and authorization scope.

The synthetic screen uses 24 propositions rendered four ways:
P chronological fact log; Q topic-organized Markdown with typed links and recorded timeline; R the same topic-organized Markdown without relational navigation or timeline view; S structured JSON with the same facts and relationships. Every original record body, status and date appears in every arm. P/R retain correction and relationship facts in prose. Q/S add redundant navigation, not new evidence.

One fresh context per arm initially, common instructions and questions, no tools/outside retrieval. These are fact-log comparisons, not raw conversations. If all arms succeed, stop this screen rather than spending tokens on repeated ceiling measurements. If a material error appears, use the already frozen reversed-question prompts for targeted follow-up and report exactly which arms were rerun. Do not interpret an adaptive screen as a preregistered powered trial.

## Frozen scoring

Gold answers and forbidden claims are in fixtures/gold.json. Each question is scored 0 (wrong/unsupported), 1 (partly correct with material omission), or 2 (correct with required provenance and qualification). Keep hallucination, stale-answer, false-publication, and false-authorization counts separate. Score warranted connection mechanisms, not exact wording.

Root scores against the frozen key; an independent review also scores the saved answers. Resolve disagreements transparently. AI agreement is not independent empirical replication. No model judge alone establishes real-world benefit.

## Actual Commons check

Use a read-only, held-out task based on the pre-existing Commons argument, its independently produced correction, and contribution instructions. Compare source documents alone versus the same documents plus a compact linked task index. Both conditions receive identical source content, not summaries with extra answers. Ask for the correct decision-impossibility target, a concrete next action, and a read-only attributed contribution with truthful publication/authorization status.

This is an exploratory usability screen. It is not a live interruption, contested multiwriter test, or long-history memory study. Exact prompts and answers will be preserved.

## Cost and stopping

Report total token and maintenance cost as unavailable, not fabricated. Corpus rendering is deterministic; researcher/source-review and note-maintenance cost remains unpriced.

A strong provisional recommendation must survive a simpler baseline, corrections, false links, unavailable information, and permissions. Do not create another repository on the strength of a tiny pilot. Implement only reversible additions inside existing Commons; assess real resumption time and maintenance effort during use.
