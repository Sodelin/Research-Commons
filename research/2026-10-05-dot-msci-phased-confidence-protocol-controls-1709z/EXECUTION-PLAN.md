## Finite resource bounds and stop rule

Every input file is capped at 16 MiB, at most 100,000 loci, 64-character restricted IDs, two ordered positive column indices at most 10^9, 160-character rational encodings/reduced 256-bit inputs, and at most 128 registry entries. The schema rejects duplicate JSON keys, noninteger/nonfinite JSON numbers, wrong labels, gaps, ambiguity and unsupported selection/admission.

Each preparation subprocess uses 512 MiB address space, a 30-second outer cap and the existing whole-attempt recursive 256 MiB polling threshold with 4 MiB receipt reserve and 0.05-second polls. Each fresh inverse producer and checker uses the same helper and 512 MiB / 150-second outer / 256 MiB whole-attempt limits, with 10-second cooperative numerical limits and the per-case 0/2/1 stage counts above. No splits are enabled. These are smaller inverse budgets than the prior arithmetic controls; no numerical cap is raised. Polling permits overshoot and is not a hard filesystem quota.

The Python dispatcher uses a finite 360-second ceiling per case, above the sum of the three admitted child outer caps; child cleanup remains owned by the reused reviewed stage helper. Inputs and outputs all contribute to the common recursive byte count. Source/import cache precautions are retained. There is no nested unmonitored producer or cross-process cache shortcut.

Advance only after terminal existence, stable source/input identities, no output/inventory failure, a complete expected composed status, and no data-confidence issuance. The three declared input refusals are expected outcomes, not a reason to run their inverse. Unexpected failure, malformed output, source change or abrupt process stop halts the batch and preserves the remaining cases as unexecuted. No retry or larger limit is inferred.
