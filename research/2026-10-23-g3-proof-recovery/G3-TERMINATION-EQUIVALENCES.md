## Source contract

joint observations with their finite legal menus, original IDs and controls.
The inherited protected template and source-word grammar is effective and
finite except for the natural number of private appends. The same physical
assignment supplies every row and paired/register component. Let Y(p) mean
existence of ONE actual finite strictly positive original realizing source.

The source/path equivalence and its limits are in sections 2--5 of the

inherited from G3.2 of the [October 16 obligation audit](https://github.com/Sodelin/Research-Commons/blob/1138a5b1a281caa00b38e0976db95b586938754b/research/2026-10-16-g3-g4-obligation-audit-1930z/OBLIGATION-AUDIT.md),
which was reread in full. Its proof is restated to connect it to the new
weighted-score/height audit, not claimed as a new source result.
For a natural N, let B(p,N) mean existence with at most N total private
appends over the protected templates. RCF and finite grammar enumeration
decide B, including N=0, and return an exact algebraic physical witness when
positive. An admitted real witness can be replaced by a real-algebraic one
for this finite formula over algebraic coefficients. This does not impose
extra algebraicity on the original source class.

Thus B is monotone in N and

    Y(p) iff exists N, B(p,N).

This inherited equivalence preserves all cores and original joint rows.
It does not assert a bound on N or closure attainment.

## A computable one-witness count bound is also necessary for a decider

The following statements are equivalent under this contract:

1. A total algorithm decides Y on every admitted encoded input.
2. A total computable natural-valued H(p) satisfies
   Y(p) implies B(p,H(p)).
3. The minimum realizing append count, with an explicit NO sentinel, is
   a total computable function.

For 2 implies 1, compute H(p) and decide the one finite formula B(p,H(p)).
The implication in 2 prevents a YES from hiding at a larger count. For
1 implies 2, first run the total decider. Return H=0 on NO. On YES, test
B(p,0), B(p,1), ... until the first success and return that N. The promised
YES supplies termination; nothing is searched on NO. This also proves 3.
Conversely a computable minimum with a NO sentinel immediately decides Y.

H need not bound all presentations. It need not vary continuously or be
locally bounded as response values approach one another. It may depend on
the entire exact encoding. The accepted high-minimum examples therefore
do not refute statement 2; they refute stronger numerical-only bounds.

If valid input syntax is decidable and finitely many strings have length at
most L, a total input-length bound H_len(L) exists effectively if and only
if the decider exists: maximize H(p) over that finite decidable list. The
mere set-theoretic existence of a maximum over finite YES descriptions is
not an algorithm to compute it.

## The canonical attained score has exactly the same effective gate

Use the entire architecture enumeration and quality maxima M_i(p) from
G3-WITNESS-BOUND-ROUTE.md, including all original strict admission slacks.
If a domain uses a finite Boolean combination of polynomial signs, split it
effectively into finitely many basic semialgebraic branches first. Each
closed relaxation then has its own continuous normalized slack product;
no disjunction is silently replaced by a conjunction or by its boundary.
Keep legal fixed intervention endpoints weak/fixed as originally specified.

Set

    S(p) = sup_i 2^(-i-1) M_i(p),
    S_N(p) = max(0, 2^(-i-1) M_i(p) for i<N).

Each M_i and S_N has an exact effective algebraic code. The tail is bounded
by 2^(-N-1); S>0 iff Y. Every S is algebraic and the exact prefix maxima
eventually stabilize, but no uniform stabilization index has been proved.

The following additional statements are equivalent to a total Y decider:

4. A total algorithm returns an exact algebraic-number code for S(p).
5. A total computable T(p) satisfies S(p)=S_T(p)(p).
6. A total computable rational g(p)>0 satisfies
   S(p)>0 implies S(p)>=g(p).
7. A total computable integer H_S(p)>=1 bounds the coefficient height of
   some nonzero integer polynomial annihilating S(p).

For 4 implies a decider, compare the coded algebraic S with zero. Conversely,
use a total Y decider: return the algebraic number zero on NO; on YES,
enumerate until one weighted term l>0 is found. Choose N whose tail bound
is strictly less than l and compute the exact S_N. No omitted term can
exceed the known l, so S=S_N. This also constructs T, setting T=0 on NO.
Computing an S_T code proves that 5 implies 4.

For 6 implies a decider, choose N with 2^(-N-1)<g(p) and compute exact S_N.
If S_N>0 return YES. If S_N=0 then S is below g, which excludes a positive
S by the promised implication, so return NO. Conversely an exact algebraic
code for S gives a positive rational lower bound when S>0; use any positive
rational, for example 1, when S=0. Thus 4 supplies 6.

For 7 implies 6, the elementary root bound is enough; no degree bound is
needed. Remove any power of x from the annihilating polynomial, so its
integer constant coefficient is nonzero if S is nonzero. Write its height
bound as H>=1. For a positive root 0<s<1,

    1 <= |a_0| = |sum_(j>=1) a_j s^j|
                <= H*s/(1-s).

Therefore s>=1/(H+1). A root s>=1 already satisfies that bound. In particular
g(p)=1/(H_S(p)+1) works for S. Conversely an exact algebraic code from 4
provides an integer annihilating polynomial and hence a computable H_S.

These equivalences do not construct any of the functions in 1--7. They
identify why finite attainment, algebraicity, approximation rates and
post-hoc algebraic heights have not supplied a simpler completion route.
An algorithm that computes S only on YES still has precisely the inherited
NO-termination gap. The classical countermodel in the companion note does
not embed halting computations into the actual G3 source class.

## Real-coefficient semialgebraic NO certificates can be searched exactly

The reduction's invariant conditions are sound by finite path induction:
for each c, Init_c is included in I_c, I_c is Trans_c-closed, and I_c avoids
the original joint target. One valid finite family excludes EVERY size.

For a FIXED finite Boolean/polynomial formula shape for each I_c, regard all
its polynomial coefficients as finitely many unknown real variables.
The three conditions, with their universal state/path-variable quantifiers,
are a first-order RCF sentence over the algebraic input constants. Existence
of real coefficients is therefore decidable. If coefficients exist, the
same finite formula has real-algebraic coefficients: the real-algebraic
field is an elementary real-closed subfield for this sentence. Algebraic
sampling gives an effective finite coefficient encoding. No rational-only
density argument is used, since strict and exact constraints may forbid
rational coefficient replacements.

Enumerating finite formula shapes and running these terminating RCF tests
therefore enumerates all NO inputs admitting finite semialgebraic invariant
families, even if their originally exhibited coefficients were arbitrary
reals. Dovetail this branch with the actual-source YES enumeration.

If EVERY original NO has such a family, the dovetailed recognizer is total.
This source-specific completeness statement is still unproved. It is only
a SUFFICIENT route to the equivalent gates above: a total decider need not
imply completeness of this PARTICULAR invariant language. Soundness and
coefficient synthesis alone do not justify that reverse implication.

## Formal and practical use

The useful conditional interface is bounded source feasibility plus witness
extraction, followed by a total-recognizer theorem that takes H and its
coverage proof as explicit parameters. Its missing premise has the full
logical strength just established. An independent optional NO-certificate
branch has all-size soundness; its completeness must be a separately named
assumption until proved for the actual source grammar.

Neither interface is a general G3 endpoint without the missing theorem.
The corresponding source/path correspondence, exact compiler refinement,
actual kernel checking and a runnable solver remain distinct deliverables.
