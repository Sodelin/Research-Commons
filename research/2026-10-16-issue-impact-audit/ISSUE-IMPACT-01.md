## Quinn: what the actual program can lose

Primary sources: Quinn, *What can we see from the road?*, [paper, sections 3, 4, 6 and availability](https://gh.copernicus.org/articles/77/165/2022/), DOI 10.5194/gh-77-165-2022; [official supplement](https://gh.copernicus.org/articles/77/165/2022/gh-77-165-2022-supplement.zip). Paper and supplementary code are CC BY 4.0. The archive downloaded here matches SHA256 `e113cc88105a34d66f8c13371a71619e20633d68125856a78f1e65cf27957e20`. Its only members are a title-page PDF and the 3,705-byte script, SHA256 `7aee3ae34ee0f4fd9e6c686dde0813f0a9e29291ff0b33d2c6022d893c42ecff`. The original was read and AST-parsed, never imported or executed.

The sequence is viewshed generation, unsigned-integer compression, removal of its uncompressed input, traffic weighting, weighted compression, removal of that intermediate. `os.system` results at lines 52, 56, 63 and 67 are unused. Removal occurs at 59 and 70. The finally counter at 76 runs after ordinary row exceptions too. CSV field extraction occurs before the try, so a short malformed row can instead stop the program before that row's finally; the counter is not even an unconditional count of all CSV rows.

| Conditional failure trace | Saved-output implication | What the counter/error text establishes |
|---|---|---|
| All stages succeed with correct fresh data | Correct binary and weighted artifacts can be saved | Counter defect does not change their values |
| Generation fails without producing raw output | No valid viewshed; missing-file deletion raises a caught exception | Error printed, then counter increments |
| Generation succeeds; binary compression fails without output | Script still removes the correct raw viewshed; both final products can be absent | Counter increments; later missing-file error is possible |
| Weighting fails after binary output succeeds | Binary output can remain usable while weighted output is missing | An unweighted analysis could stay intact while weighted analysis changes |
| Final weighted compression fails without output | Raw weighted intermediate is still removed; final weighted output absent | No Python exception is necessary: removal can succeed and only processed text prints (external utility may emit an error) |
| Failed stage leaves a pre-existing target untouched | A later stage can consume stale data; binary/weighted outputs can describe different runs | Neither count nor file existence checks freshness |

The last scenario is conditional on failure behavior and pre-existing artifacts; an actual utility may instead truncate a file or leave a partial one. These outcomes require validation, not guessing. A cleanup failure can also prevent later weighted work despite a good binary result. The independent `row_model` uses only Python dictionaries and in-memory removal; it executes no external command or deletion. Its six traces make those conditions inspectable in [CONTROL-RESULTS.json](CONTROL-RESULTS.json).

**Causal distinction:** incrementing the counter does not itself alter raster pixels. Ignoring a failed subprocess and continuing/deleting can. A missing/stale raster affects the published cumulative map only if the actual aggregation consumes an incomplete or wrong collection, rather than detecting the problem and repairing/aborting. The supplement omits the cumulative-summation implementation. The paper says binary rasters were summed successively with GDAL Calc, and weighted rasters were summed too; it does not document the counter as an acceptance gate. No evidence found supports that stronger allegation. Published maps demonstrate some output existed, not completeness of every expected row.

## Quinn: downstream stability is not automatic

Write C for the correct unweighted sum and L for the sum of independently validated surviving rasters. For k genuinely omitted binary rows on the same grid, `L <= C <= L+k`. With nonnegative traffic weights the bound is `L <= C <= L+M`, where M is total omitted weight. This bound does **not** apply unchanged to an unvalidated partial sum containing stale/corrupt rasters; those must first be excluded or separately bounded. Missing binary rows only lower counts, but data-dependent selection can still add or remove selected features.

1. **Raw sums, rankings and visibility.** One omitted row changes a cell exactly when that row sees it. A correctly zero-contribution omission leaves that cell unchanged. A fixed threshold is stable if its entire `[L,L+M]` interval lies on one side. The reported Rainier maximum of 2104 viewpoints cannot be certified against other pixels without the actual runner-up margins and missing registry. A positive I-90 visibility union remains positive after adding missing rows; observed zeros may turn visible. This is conditional protection for validated data, not certification of Figure 3.

2. **One-kilometre maximum filtering.** For a fixed neighborhood N, `max_N L <= max_N C <= max_N L+M`. It is unchanged if every possible omitted contribution stays below an unchanged winning maximum. It can change when a rival becomes larger. The executed examples `[5,2,1] -> [5,3,1]` leave the maximum at 5, whereas `[5,4,1] -> [5,6,1]` raise it to 6. A localized change can influence every output neighborhood containing it; maximum filtering spreads a peak's influence and is not a generic error-removal operation.

3. **One-kilometre median filtering.** Order-statistic monotonicity gives the analogous M bound, using the same mask/neighborhood and convention. A changed outlier need not move the median: `[10,10,11] -> [10,10,12]` stays 10. But `[10,10,11] -> [10,11,11]` crosses the district rule `>10`. Rounding, nodata handling and resampling must also be fixed. The paper's resampling kernel/origin and median tie/rounding details are not a complete executable contract. Slope is independent of missing viewshed rows if the DEM is unchanged; the visibility part of the joint slope/visibility test is not.

4. **Percentile selection.** For fixed nonzero support and a specified top-rank/tie rule, an accepted/rejected boundary gap greater than M protects membership under one-sided missing additions. More generally use filtered lower/upper bounds: every selected lower bound must exceed every rejected upper bound for a sufficient strict separation certificate. Ordinary percentile thresholds are data-dependent; fixed 153/380/10 tests alone do not certify them. Our declared top-5% rank fixture switches the winning cell from 153 to a previously 152 cell after two omitted binary contributions raise it to 154. If zeros become positive, the number of ranked cells can change too. Under the fixture's explicit ceil convention, 20 to 21 positive cells changes the top-5% count from one to two, even without changing the largest values. This is an illustration, not an assertion that Quinn used that convention. Ties and nonzero-support changes must be tested on the real rasters.

5. **Polygon merging and cutoffs.** Equal binary masks plus identical operations imply equal polygons. Changed masks need not. The paper merges gaps below 5 km, removes polygons/holes below 25 km², optionally demands a top-1% pixel (reported cutoff 380), and for districts requires over 30 km of highway. An illustrative grid configuration has two 24 km² rectangles separated by exactly 5 km: neither survives the area rule. One attached 1 km² cell reduces the gap to 4 km; the merged patch has at least 49 km² and survives. This is a threshold-mechanism construction, not a simulation of unspecified GIS aggregation details. Highway-length and top-1% gates can similarly switch at their boundaries. No generic small-pixel-error guarantee protects topology or the final hand-digitized labels.

Consequently the defect can affect counts, weighted emphasis, selected peaks, district candidates, scenic-viewpoint ranking and manual inputs. Conversely, complete correct outputs, zero omitted contribution, protected rank margins or unchanged masks can leave particular outputs unchanged. The paper's methodological demonstration that cumulative viewsheds can inform cartography is not refuted by a possible failed row. Specific empirical numbers/features require run evidence, not this general defense or a generic failure warning.

### Curvature branch and feasibility

The methods say 0.85417; code explicitly passes 0.85714. Using the documented GDAL correction `c*d²/(2R)` with illustrative `R=6,371,000 m`, their difference is about 0.0233 m at 10 km, 0.583 m at 50 km, 2.331 m at 100 km and 9.323 m at 200 km. These are executed formula evaluations, **not measured visibility errors**. Near-horizon binary decisions can flip; no affected-cell count follows without terrain and line-of-sight margins. The default recommendation does not identify the historical parameter. [GDAL's formula and current return-code contract](https://gdal.org/en/stable/programs/gdal_viewshed.html) are version-qualified documentation, not a substitute for the original binary.

The paper identifies approximately 30 m USGS DEMs projected/mosaicked/clipped to Washington, 2019 WSDOT highways/AADT, 1 km route samples, tunnel exclusions and a spatial join yielding 11,225 points. Neither processed input is in the supplement. Portal links do not fix historical tiles, reprojection grid, route starts, tunnel exclusions or join choices. The paper's 38 s per viewpoint implies about 118.5 serial hours for its per-viewpoint stage alone. This environment exposes GDAL 3.10.3, but that is not the historical build; no full reconstruction was attempted. Exact historical inputs and downstream recipes, rather than merely software installation, block a defensible study reproduction. A reconstruction from current public data could study sensitivity later, but would not establish what happened in 2022.

## Ge: identity conflict and conclusion sensitivity

Primary source: Bradford et al., [PMC author manuscript, DOI 10.1039/D2CP04492G](https://pmc.ncbi.nlm.nih.gov/articles/PMC9731815/). Directly read here: Figure 2/prose identify 4merI at +11.7 kJ/mol; Table 1 names 4merE with coefficient `5.13e-4 ± 4.8e-5` and ratio 0.19. ### What follows, and what does not

**Branch I — label-only table repair.** If the fitted vector was I and only its displayed name became E, changing the label changes no predicted intensity, residual, coefficient, standard error, AIC or abundance ratio. Multiple prose/figure identifications and the reported SI highlight favor this as an explanation of intended identity; counting those mentions is not proof of numerical provenance. Calling it a confirmed typo would go too far.

**Branch E — table row is numerically literal.** If the coefficient belongs to E's distinct geometry, changing the interpretation to I without refitting is unjustified. The exact motif, energy difference (5.5 versus 11.7) and structural-growth narrative may change. From the present inspection we cannot certify whether E would require the same rearrangement as I; a drawing described as “different” is insufficient for that conclusion. Both reported energies remain above A, so the narrower non-global-minimum interpretation survives this identity ambiguity **conditional on either assignment being supported by a valid fit**. That does not certify population or kinetics.

**Different objects are not merely different names.** In a mixture `y ≈ B b + a t`, relabeling the unchanged t has no numerical effect. Replacing t_I by t_E at fixed a changes prediction by `a(t_E-t_I)`. After profiling the other columns B, only the residualized difference matters: if the two residualized columns are collinear with an allowed coefficient transformation, the data can be unable to distinguish them; otherwise a refit can change residuals and selection. Our explicit synthetic vectors give SSE 0 after renaming, SSE 8 after fixed-coefficient substitution, and SSE 4 after refitting the alternative. None is a measured diffraction calculation.

The label conflict alone does not refute detection of molecular scattering, the dimer/trimer components, or the practical possibility of fitting cluster mixtures. Nor does it independently refute or validate the dimer-spacing claim: changing a tetramer template in a correlated fit can alter other coefficients, so numerical invariance cannot be presumed. A small reported conditional standard error on the tetramer coefficient is not a test of which template label is correct, and does not account by itself for model selection or correlated templates. The paper's qualitative model-selection conclusions are weaker than a universal calibrated structural certificate; failure to supply such a certificate is not itself a defect in its stated regression exercise.

### Exact unavoidable empirical block

To distinguish the two branches requires the original table-producing design matrix (geometry-to-column identifiers), measured and neat-helium vectors on the fitted grid, the selected fit/coefficients and preprocessing, and coordinates or exact templates for E and I. To assess statistical robustness also requires group membership, significance/plausibility/tie rules and an adequate noise/error model. Figure digitization cannot recover that identity chain or unrounded numerical data. The reported SI supplies illustrated structures, not the missing numerical regression record. No original fit was rerun and no calibrated confidence statement is claimed.
