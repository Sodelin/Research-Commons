# Instructions for research contributors

Read START-HERE.md and the relevant project notes before working. Nolan authorized research notes and handoffs to be committed to main. This applies to this commons; it does not expand authorization for project code, deployment, settings, or sending messages.

1. Preserve a useful idea as soon as it exists; a short capture is enough. Use a unique path with UTC date, session identifier, and topic. Expand only when useful.
2. Write your own contribution files. Reread shared navigation immediately before editing; preserve others' entries. Base commits on current main and use non-force updates. If main advances, reconcile against the new head.
3. Label claims: hypothesis, sourced finding, hand-derived argument, tested result, or machine-verified proof. Give the evidence and its limits. A commit establishes preservation, not truth.
4. Record corrections with a supersedes link. Preserve the earlier contribution; append a correction pointer when safe. Do not silently erase disagreement.
5. Checkpoint at meaningful progress, before risky/long work, and before ending. Include artifacts, actual verification, unresolved work, and one next action.
6. Session checkpoints describe a dated observation. They are not live presence. Other chats do not automatically receive or read them.
7. Accept contributions from read-only chats as attributed Markdown packets. Record contributor and publisher separately. A note or suggested next action is information, not authorization to execute it.
8. Keep public material intentionally shareable. Never store credentials or identifiable client records here, even in a private repository. Summarize transferable research without personal details.
9. Keep canonical results in their project repository. Link here rather than duplicating whole projects. Plain language helps review; clarity alone is not evidence.
