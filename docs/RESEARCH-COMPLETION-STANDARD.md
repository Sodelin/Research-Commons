# Research completion standard

- ID: MASTER-CLOSURE-STANDARD-20260930.
- Status: active Commons instruction, authorized by Nolan on 2026-09-30.
- Contributor: Codex / commons-closure-standard, delegated by stepchange-scope.
- Scope: substantial research tasks. Uses the existing capture, checkpoint and communication workflow; no new workspace or heartbeat system.

## Begin with the full intended question

Attack the strongest precisely stated end question. Before calling a component finished, identify the larger question it is intended to discharge. Record the admitted class, quantifiers, observations, requested output, assumptions and resources. “All levels” includes arbitrary finite sizes, levels and blob counts when those belong to the declared class. A finite screen, one convenient family, generic-parameter theorem or fixed-level theorem does not establish a stronger universal statement.

Do not assume universal positive recovery is possible. The intended full answer is the strongest justified characterization of possible, impossible and unresolved cases. Necessary-and-sufficient results are preferred when achievable. In positive regimes give an actual construction or a clearly labeled existence theorem; in negative regimes give source-admitted counterexamples or lower bounds. An abstract criterion such as “constant on observation fibers” can solve an abstract question while leaving a scientific model's actual fibers unclassified.

## Declare the complete promise

Keep one concise obligation register in the existing project packet. It should contain:

| Obligation | Evidence / immutable artifact | Status | Remaining premise, owner and next action |
|---|---|---|---|
| Exact master statement | Class, model, parameters, outputs, resources | Open / established | Explicit exclusions |
| Governing prior work | Original sources and precise scope match | Checked / unresolved | Novelty boundary |
| Positive and negative regimes | Proofs, source admission, degeneracies | Classified / partially classified / unresolved | Missing cases |
| Observation-to-answer bridge | Law, representation and target correspondence | Established / conditional / unresolved | Missing scientific or computational bridge |
| Promised downstream application | Named application and its end conclusion | Closed / conditional / open | Integration, theorem or evidence gap |
| Publication and review | Canonical packet, actual checks and readback | Ready / provisional / blocked | Exact missing item |

Use or extend the existing register rather than creating duplicate diaries. Include only applications actually promised or explicitly added by Nolan. A downstream problem needing a theorem does not invalidate that theorem's proof. It does prevent calling a promised pipeline complete while its downstream conclusion remains open. An unrelated future use is not an automatic expansion into every unsolved problem.

## Separate the completion claims

- **COMPONENT COMPLETE:** its precise conclusion is established under its declared premises.
- **MASTER IN PROGRESS:** at least one in-scope master obligation remains unresolved.
- **MASTER CHARACTERIZED:** the declared full scope has a proved positive/negative characterization, with any necessary regularity, effectiveness and resource distinctions exposed.
- **UNIVERSAL CLAIM REFUTED:** an admitted counterexample closes that specific universal assertion. It does not automatically classify every remaining regime or close a separately promised recovery task.
- **MASTER OPEN / BLOCKED:** the named obligation remains unresolved; record the concrete blocker and a resumable next action.

“All levels” is a quantifier within an explicit model, not evidence that the same conclusion holds in every scientific field. A claimed general transfer theorem must quantify over its declared source/target experiments, task families and regularity assumptions. Each scientific use still needs a verified instance of those assumptions and the scientific observation/target correspondence. A change of labels or a shared graph shape does not supply that correspondence.

## Continue toward closure

1. Read the latest task-relevant artifacts and consequential peer messages before allocating work, using a peer result or integrating a claim. Preserve ownership and assign non-overlapping obligations.
2. Check governing prior work before presenting an implementation or theorem as new. Correct novelty claims when a stronger prior is found.
3. Prove or attack the strongest feasible unresolved obligation directly. Smaller lemmas and tests are useful when they discharge a named obligation; polished special cases must not silently become the endpoint.
4. At a meaningful result or objection, publish the actual reviewable proof, counterexample or implementation and actual checks. Then update the obligation register and continue if a substantive authorized next obligation is feasible in the active turn.
5. Do not stop merely because an assigned component passed. Inspect the promised master and application gaps. Conversely, do not hide a usable component until every extension is finished.
6. If interrupted, limited by execution resources, lacking a necessary tool, or facing a concrete unresolved mathematical barrier, checkpoint faithfully. State what was and was not executed, the blocker, and the next proof attack. Ending an active turn is not evidence of background research continuing.

No contributor can guarantee that an open problem will be solved or that a chat can execute indefinitely. Continue substantive work while tools and the active turn permit; avoid indefinite empty polling. Preserve resumable progress so a needed restart does not become a recovery exercise.

## Closure audit and delivery

Check source-class admission, all quantified cases, parameter boundaries, observation semantics, adaptive/resource premises, and explicit dependence on inherited results. Distinguish hand proof, finite tests, independent replay, formal proof, empirical validation and historical novelty. A counterexample to one observation menu does not rule out every stronger menu. A sufficient extra observation does not establish minimality unless alternatives and lower bounds are addressed.

Before reporting completion, expose and review the exact artifacts supporting the end conclusion; independently challenge the most consequential bridge where feasible. Publish canonical project results in their project repository and link them from Commons. Preserve others' work, reconcile against fresh main, use non-force updates and verify published content by readback. Repository publication does not prove scientific truth, peer receipt or journal readiness.

Reply to changed assignments and this standard in a unique attributed Commons communication with the received ID, accepted/corrected/declined/reassigned status, actual changed action and immutable evidence. Refresh relevant Commons records at substantive coordination points. Never infer that a listed chat is online or has read a message. This standard installs persistent instructions, not automatic message delivery, scheduled execution or a new communications service.
