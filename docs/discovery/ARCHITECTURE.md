# Component choices under the Why not Rust protocol

Choose tools for the product, integration, trust boundary and actual workload. Language is a component decision. Canonical source owner: Dot; discovery interface owner: github-maintainer-auditor; Lean E2E supplies the established PR3 gateway and evidence joins.

## Reuse inspected

Existing claims.json, CLAIM-BOARD, START-HERE, WORKFLOW and current status/duplicate-work audits are the scientific base. Exact JSON bytes, commit, digest and authorship are in dist/source.json. No parallel registry is created. The Lean gateway inspected the six-file introducing commit and current curation workflow: no generator command in those specific sources. This is bounded evidence, not proof that no prior site exists.

Existing phone native filename/fuzzy picker, supplied-transcript literal search and portable search core have different selection/literal/cursor contracts. They do not supply weighted question/assumption/prior-work retrieval. Their callable/privacy boundaries remain owned; no source or binary is silently substituted. Existing process/recovery systems remain untouched.

The public applications subtree was inspected untruncated; scientific-integration is a report/solver route. Earlier unlocated websites remain a reuse gap, and Lean asked Dot for exact overlapping tooling. This is not an exhaustive global-site census.

## Security and privacy

Only intentionally public authored claims and proof/status links enter the bundle. No private routing, runtime records, prompts, credentials or session archives. Search ranks locally and never posts queries or calls a model. Source-update fetches use public GitHub. Shared search URLs can contain the query; this is not a platform-log invisibility claim.

All source values use textContent. External links require HTTPS/noopener. Data is never evaluated as code. MiniSearch package scripts were not run; SHA512 package integrity was checked and ESM SHA256/licence retained in DEPENDENCIES.json. Test dependencies are excluded from deployment. No tokens enter the bundle.

Latest-source failure preserves the dated bundled snapshot with a visible notice. Duplicate IDs, invalid cards or dangling relationships refuse a replacement. Candidate connections remain candidates; shared principles are not theorem dependencies. Unindexed work is an explicit coverage gap, not mathematical absence.

## Recovered prior reader and source policy

An earlier first-party Atlas reader was actually recovered and inspected. Its safe prose renderer, pinned 12-article/glossary edition, strict link boundary and source tests exist. Its fixed article schema and narrower host allowlist do not fit the current scientific claim register, so neither that schema nor private article bytes were copied. Its credential-bearing link refusal was adapted to this reader while retaining extensible scientific publisher domains. Current controls reject userinfo, nonstandard ports and sensitive/signed query keys before accepting a source replacement. Those are scoped URL checks, not comprehensive content redaction or a network sandbox.

Bibliography lookup now recovers canonical prior_work / historical_problem_statement links as well as origin.source_url, deduplicates them and preserves their actual roles. It does not attribute the project's stronger theorem to a prior paper. The same adapter supplies ranking and reuse export. A source URL missing from one field is not called absent when another declared reference supplies it.

`tools/refresh.py` invokes the SAME model's stdin validator before first snapshot persistence; input remains in memory and an invalid source refuses. Browser/CLI use the same policy. `tools/check.mjs` resolves explicit suite paths from its own module, avoiding accidental zero-test success under another cwd. No old application was changed, redeployed or assigned a new owner by this recovery.

## Evidence-body retrieval decision

The retained rust-connectors SUBSPACE-CONNECTOR contract searches ten bounded coordination documents and, separately, handoff/candidate filenames at its validated private source commit. It does not offer research-body retrieval; its existing cache and owner remain unchanged. This reader therefore projects already-public immutable evidence references from the canonical register into the SAME static deployment, rather than adding a private cache service or competing registry.

Pagefind's official Node API supports addCustomRecord, in-memory index generation and chunked static output (https://pagefind.app/docs/node-api/). That is the preferred candidate when broader archive coverage makes transfer size or startup unacceptable. For the measured initial 133 documents/1.34 MB body corpus, the already pinned MiniSearch adapter reuses the browser/agent interface, has no native installer or server lifecycle and keeps complete auditable input source. This is a measured first corpus, not a rejection of Rust/Wasm. Full-archive expansion must evaluate chunked Pagefind against actual transfer, startup, query latency and agent export requirements. Tantivy remains a candidate for a maintained native/server source owner; no such new service is needed for this bounded static projection.

Content is rendered with textContent and existing HTTPS-safe link construction. Only immutable first-party Markdown URLs in the public canonical artifacts are selected. No embedded Markdown is executed or rendered as HTML; original content remains linked for full context. Hashes identify the fetched bytes, not independent mathematical acceptance. The original source cache, Dot's claim model, scientific dispositions and private/public boundary are preserved.

## Public source-path expansion and recovery contracts

Root recursive Git listings were known truncated. The archive exporter instead pins one main commit, obtains selected root tree IDs, and batches up to25 exact Git tree objects through GitHub GraphQL. It traverses6selected public source roots, records32explicit excluded dependency/generated/self paths and emits only regular Markdown publication metadata.7,794exact trees/105,112entries yield5,829source paths; symlinks/submodules, raw runtime/session material and private project metadata are not imported. This static projection is the source artifact, not a new maintained cache/server or claim register. Search uses the same pinned MiniSearch engine and browser/agent contracts; larger body retrieval still needs the independently documented Pagefind evaluation.

The recovery contract is explicit rather than guessed: the canonical original.G3 RESULT-CATALOGUE.json / SOURCE-MANIFEST.json pair supplies16 component keys and58 public authored notes, with exact public identities. Literal source roles and review/formal gaps are retained. Other future catalogue schemas are refused until their owner supplies a supported contract. The catalogue README is source correction context; unelaborated Lean sources remain metadata outside Markdown-body search. Native/controller or master-claim completion is not inferred.

Claim filters preserve raw source fields. Subjective reuse sorting is a separate dated overlay with explicit author, reasons, purpose and source; unranked items retain null rank and do not receive a zero score. Historical novelty text and review/completion remain separate. Source-layer pagination avoids unbounded agent output, and archive-path results cannot masquerade as status-filtered proof records.

Owned reading joins use the existing source-body engine as a separate projection role, `owned_reading_join_source`, carrying the literal `source_join_kind`. Import checks every claim identity and link before fetching, selects only pinned public first-party Markdown, and merges source references without changing canonical accepted_artifacts. Dot’s exact declaration/module guide supplies reusable hypotheses and exclusions; source matching grants no kernel/native/package acceptance.

Snapshot comparison is a read-only projection in the shared model. It validates both endpoints, matches stable canonical IDs, ignores object-key ordering, preserves array-order changes and lists added/changed/absent cards with changed top-level fields and scoped before/after summaries. Browser and CLI consume the same result. It does not infer when an intervening proof happened, treat missing cards as deleted evidence or assign novelty. No additional registry/backend is introduced. Refresh failure retains the actual loaded source and its comparison provenance.
