## 3. Four distinct meanings of “one change”

1. Fix one parent choice so the target occurs for EVERY assignment of all other choices: a one-switch sufficient certificate.
2. Flip at most one bit from a given complete switching: a distance-to-success question.
3. Force one parent choice, then retain independent natural randomness at all others: a controlled probability question.
4. Select one common control/setting that improves ALL targets together: a simultaneous recovery question.

These quantifiers are different. The equality example with only successful setting 11 cannot be reached from 00 by one flip, and has no one-bit sufficient certificate. It can still benefit probabilistically from one forced choice.

## 7. Do not reduce maximality to certificate size

A one-bit accepting certificate is sufficient, but not generally necessary, for a passive probability guarantee >=g. Abstract counterexample: E12 accepts every three-bit string except 000 and 111. Every one-bit cylinder contains one excluded endpoint, so none forces acceptance. Yet its minimum independent product probability over [g,1-g]^3 is 3g(1-g)>=g.

Derivation: its probability polynomial is p1+p2+p3-p1p2-p1p3-p2p3. It is affine separately in each parameter, so a minimum lies at a corner. The all-equal corners give 3g(1-g); mixed corners give 1-g+g², whose difference is (1-2g)²>=0. The Boolean function and polynomial are prior Example 3; the parameter-box consequence is an elementary calculation here. No claim this event is realizable as a source-network split is made.

The strongest class-specific request must therefore consider all successful switchings and their probabilities, not declare “mass>=g iff one-switch certificate.”

The equality witness is a mandatory test of any such reduction.
